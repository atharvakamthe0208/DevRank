# Scoring rules

Official score calculation belongs in `apps/api/src/modules/scoring` and is deterministic. The active contract uses five categories in `packages/contracts` and versioned role weights from `config/role-weights.json`. The current scoring version is `2.0.0`. The weights remain preliminary and need team agreement; they are not scientifically validated hiring criteria. Six-category v1 snapshots are historical and have a separate read-only validator.

For a category with multiple evidence items, score is the arithmetic mean of available evidence items with valid normalized values. Each category mean is rounded to two decimal places using nearest-hundredth rounding. Evidence that is missing or has no normalized value does not participate and is never converted to zero. An invalid evidence item or invalid weight configuration causes a clear `ScoringValidationError`.

Overall score is calculated only when all five category scores exist: `sum(category score × role weight) / 100`. It is rounded to two decimal places after weighting the already rounded category scores. If any category is missing, the response includes available category scores and missing category IDs, sets `insufficient_evidence`, and omits `overallScore`. The partial-evidence renormalization formula is not used under the current strict scoring policy.

The scorer validates its output against the shared evaluation response schema and always includes `scoringVersion`; the response schema keeps that field optional to accept older payloads. Unsupported or mismatched versions are rejected. It does not call an AI service; AI explanations remain separate and cannot change numeric scores, weights, evidence, or evaluation status. See [Day 4 scoring versioning](day4-scoring-versioning.md) for the version policy. The category averaging and rounding choices are implementation rules for the MVP and should be reviewed with the team before production use.
